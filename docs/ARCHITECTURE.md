# Architecture and persistence

Project Version: 0.1.0-dev.1

Initial project creation establishes canonical VERSION and API 1; no prior UI project version exists. This is an extracted foundation, not fulfillment of the full-overhaul audit. Authority is client presentation only: no server module, gameplay ModData, custom network commands, inventory mutation or game-state ownership. Normal client Lua load paths expose the API. Dedicated servers may install the mod as a dependency but do not load client widgets; runtime verification is pending.

Core: Theme/Renderer/Controls/Dialog/Tooltip/RowTooltip. Public API composes them and caches a facade per consumer. Instance factories/style mark consumer scope; dialog/tooltips inherit it. Appearance settings are separated from callbacks/layout and isolated by local-player slot. AppearanceEditor loads only when opened. Clipboard contains original pure Lua geometry and application-supplied title. No global native class monkeypatch. No per-tick UI/world scan is introduced.

Appearance reads the engine cache/Lua directory via getFileReader(..., false). Expected data: one `opacity=N` line, finite 20–100, default 82. Scoped path is `B47ANCEDUI/appearance/<consumer>.<player>.txt`. Registered read-only legacy fallback imports Quartermaster's former `B47ANCEDQuartermasterAppearance<player>.txt`; explicit save writes only the scoped path. Other consumers and players remain isolated. Existing legacy files remain available for downgrade. After a new UI-only preference change, downgrade to old Quartermaster reads the last old value; no reverse synchronization is claimed. Missing/corrupt scoped values fall back to a valid registered legacy value or default. Read errors close the reader; save errors close writer and return false. Native writer silent I/O failures/atomic durability are not established by protected calls. Existing editor behavior remains preview/save-on-close; full transactional profile recovery is future scope.

Theme/renderer tokens are shared, read-only-by-contract; per-consumer arbitrary themes are not implemented. Application window persistence/minimums, row semantics, labels and callbacks stay application-owned. Quartermaster's rail geometry/window filenames remain unchanged. Client presentation needs no server sandbox settings; a future gameplay option would require a separate server-authority design.

Provenance pins the owner-approved Quartermaster source commit, version and original hashes. Tooltip/appearance labels now belong to UI's JSON tables, with matching key coverage in all 29 source locales and explicit unreviewed English fallback. The UI mod is excluded from generic fallback-art policy; it ships no invented branding/Workshop ID. No custom Java/bridge/JAR is included or required.
