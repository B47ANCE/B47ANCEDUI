# Architecture and persistence

Project Version: 0.9.0-dev.3

NativeSettings adds an instance-scoped Options palette/drawing adapter. Native settings retain their original values, callbacks, fonts/geometry, tabs, page stencils, display confirmation, audio rollback and input ownership. Supported late additions are adopted through owned container addChild delegates, with bounded initial traversal. Custom renderers and colour swatches remain guarded; shared dropdown popup fields/methods restore after themed draw/error and detached controls stop receiving drawing changes. Accent is UI's local slot 0; no gameplay state, new settings storage or public API changes. See NATIVE_SETTINGS.md for scope, evidence and runtime gates.

Initial project creation establishes canonical VERSION and API 1; no prior UI project version exists. This is an extracted foundation, not fulfillment of the full-overhaul audit. Authority is client presentation only: no server module, gameplay ModData, custom network commands, inventory mutation or game-state ownership. Normal client Lua load paths expose the API. Dedicated servers may install the mod as a dependency but do not load client widgets; runtime verification is pending.

Core: Theme/Renderer/Controls/Dialog/Tooltip/RowTooltip. Public API composes them and caches a facade per consumer. Instance factories/style mark consumer scope; dialog/tooltips inherit it. Appearance settings are separated from callbacks/layout and isolated by local-player slot. AppearanceEditor loads only when opened. Clipboard contains original pure Lua geometry and application-supplied title. No global native class monkeypatch. No per-tick UI/world scan is introduced.

Appearance reads the engine cache/Lua directory via getFileReader(..., false). Expected data: first line `opacity=N`, finite 20–100, default 82; optional `accent=#RRGGBB`, default neutral grey #B0B0B0. The reader inspects at most eight records, accepting up to 128 characters per line, keeps the first valid value of each recognized field and ignores unknown/invalid fields independently. A non-default accent is written after opacity; the default is omitted to preserve the old opacity-only format. Legacy import includes opacity only. Older versions read the first opacity line but drop custom accent on their next save. Scoped path is `B47ANCEDUI/appearance/<consumer>.<player>.txt`. Registered read-only legacy fallback imports Quartermaster's former `B47ANCEDQuartermasterAppearance<player>.txt`; explicit save writes only the scoped path. Other consumers and players remain isolated. Existing legacy files remain available for downgrade. After a new UI-only preference change, downgrade to old Quartermaster reads the last old value; no reverse synchronization is claimed. Missing/corrupt scoped values fall back to a valid registered legacy value or default. Read errors close the reader; save errors close writer and return false. Native writer silent I/O failures/atomic durability are not established by protected calls. Existing editor behavior remains preview/save-on-close; full transactional profile recovery is future scope.

Theme/renderer tokens are shared, read-only-by-contract. Accent overrides are cached per consumer/local player; shared Theme tables are never mutated. Shared rendering resolves original accent/hover/selection tokens at draw time, so existing windows update immediately; semantic status colours and normal text remain independent. Native list selection is refreshed per instance. Raw consumer drawing must request Appearance.color(widget,token); copied colour snapshots do not auto-update. Editable component presets now layer above those legacy preferences; arbitrary provider rendering and fonts remain opt-in/caller-owned. Near-black/grey-default styling rounds only owned instance backing rectangles using cached scanlines, radius capped at 8 and half the widget bounds. Each fill/perimeter pass avoids overlapping alpha; native textures, input callbacks and rectangular hit boxes remain unchanged. No global native class modification. Draw cost is bounded by radius, not window area; native performance and texture corners remain runtime gates. Explicit Small/Normal button helpers (legacy Large requests alias Normal) adjust height/font/padding, while legacy constructors and metrics preserve consuming application layouts. Application window persistence/minimums, row semantics, labels and callbacks stay application-owned. Quartermaster's rail geometry/window filenames remain unchanged. Client presentation needs no server sandbox settings; a future gameplay option would require a separate server-authority design.

Provenance pins the owner-approved Quartermaster source commit, version and original hashes. Tooltip/appearance labels now belong to UI's JSON tables, with matching key coverage in all 29 source locales and explicit unreviewed English fallback. The UI mod is excluded from generic fallback-art policy; no fallback artwork was added. Workshop item 3822582242 now carries 0.5.0-dev.11 MP test distribution; earlier upload evidence remains historical. See WORKSHOP_PIPE_UPDATE.md for the current receipt. Upload does not verify native UI or dedicated behavior. No custom Java/bridge/JAR is included or required.

MenuButton is an additive client component intended for main/pause/Esc-style navigation. Native ISButton owns enabled/pressed/click/controller behavior and render callbacks. Instance-only styling suppresses its backing/border, selects native UIFont.Large and left alignment, then uses the existing fitted-title/native render path with label-only accent underline. Generic boxed focus/role decorations are skipped for this kind. Consumer supplies localized labels and behavior. Ordinary Small/Normal controls and the old Large→Normal alias are unchanged.

NativeMenus is a separate auto-loaded client adapter, requiring native MainScreen before registering OnMainMenuEnter/OnGameStart/OnResetLua callbacks. It also decorates an already constructed instance on load. A fixed allowlist matches native field/internal ID, ISLabel type, direct bottomPanel parent, Large font and native mouse/render entrypoints before changing only each label's prerender. Duplicate callbacks or reloads do not stack wrappers. No MainScreen/ISLabel class method, event dispatcher, pause/resume/key handler, action callback or controller row is replaced. The native fade update, tooltip and controller glyph draw path remain; the grey hover backing is omitted and Renderer.menuUnderline is shared with MenuButton. Temporary fitted text and colour are restored even on error. The label-style adapter alone retains native width/height/position. The separate 0.5 background adapter adjusts main-menu column geometry as described below. No tick scans or world/player queries. Native scope is B47ANCEDUI, slot 0. Guarded or unrecognized menu items are untouched; exact entrypoint replacements by another mod remain a compatibility runtime gate. See NATIVE_MENUS.md.

## Options and local HUD geometry (0.7.0-dev.1)

OptionsInterface adds one owned page through native MainOptions.addPage, restoring the root's page pointer/addY and retaining native stencils/controller setup. Its actions open appearance, the style preset inspector or the safe HUD workspace. It neither replaces Apply/Back nor writes native game settings.

UILayout stores a separate data-only schema1 profile; LayoutAssets exposes provider-scoped register/resolve/apply through API1. HUDPreviews builds original synthetic panels, never gameplay widgets. UILayoutEditor owns a black root, scaled canvas, transparent hit overlays and compact inspector. EditorControls shares final-bounds native slider pagination, larger thumbs, steps and batched numeric entry with the existing menu editor. Existing defaults/schema/files remain unchanged.

HUDLayoutRuntime requires native registration modules before its callbacks and applies explicit saved geometry after restoration. Bounded current local-player slots and exact widget types guard bindings; controller layouts are skipped. The instance-owned hotbar delegate reapplies position after native recentering, without a new global tick/file read. Minimap userPosition changes only for a configured override; mechanics retains native content-dependent width. Fixed native sizes and reference-only clock/moodles remain explicit. No gameplay state, server sandbox option, network message or save mutation is introduced. Unknown provider records survive normal saves; future/error/overflow files require explicit Reset before replacement. Native layout.ini is never edited; its ordinary persistence can retain geometry after our override is released. Full contract/evidence: UI_WORKSPACE.md. Native SP/split-screen/controller and dedicated acceptance remain NOT TESTED.

The 0.7.0-dev.2 exit guard stays in EditorControls and the two owned editors. Each snapshots saved data on open; voluntary exits compare draft and pending text, then open an owned child scrim/panel if needed. Keep is the default; Discard performs existing unconditional teardown without writes. Capture, tooltips, numeric and underlying child-controller focus are released for the prompt; native child focus/pending text return on Keep. No detached UIManager/modal root is introduced. Save success and forced lifecycle teardown use unconditional cleanup; duplicate/stale callbacks cannot close a later editor. Existing saved formats, gameplay/network ownership, defaults and public API remain unchanged.

## Local style presets (0.9.0-dev.1)

StylePresets owns a separate data-only schema1 two-slot journal per local player. ComponentStyles resolves immutable Theme/Appearance defaults through the selected preset shared/all/family and optional consumer overrides, caching by player/revision/scope/family. Native/API palette wrappers restore inherited colors before each refresh; slider pagination snapshots native geometry and keeps value mapping unchanged. Detached native sliders restore native dimensions. No new gameplay state, network channel, sandbox setting or world scan. Public API1 adds Slider/Styles/StyleEditor only.

StyleEditor owns a viewport veil, a stable scrollable inspector and an opt-in preview subtree. A copied draft and single-owner preview lease separate live rendering from saved data. Save alternates journal slots and verifies read-back; Cancel restores saved data; invalid pending name/value fields cannot be cleared by editing another field. The shared exit guard protects voluntary unsaved closes; actual lifecycle teardown removes owned resources without writes. Frontend/player controller focus is transferred explicitly and restored only while owned. File failure/durability limitations, current validation and custom-renderer exclusions are recorded in STYLE_PRESETS.md.
